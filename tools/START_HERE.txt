航管知识图谱：第一次接手直接照着做（Windows）
============================================

所有命令先进入项目根目录：

  cd /d D:\Data\项目代码\atm-knowledge-graph-baseline


项目模块和问题定位
==================

数据读取
  位置：infra/source
  问题：Excel/Oracle 数据读不出来时先看这里；两者都先用 source-preview 看 SourceRecord。

本体和字段映射
  位置：infra/ontology、infra/mapping、infra/identity
  问题：源数据正确，但实体、属性、关系或 UID 不对时先看这里。

同步更新
  位置：service/sync、infra/trigger
  问题：源数据变了，但图没有跟着变化时先看这里。

图存储
  位置：infra/neo4j
  问题：映射结果正确，但 Neo4j 写入结果不对时先看这里。

图查询
  位置：infra/query、service/query
  问题：图里数据正确，但实体、一跳、K 跳、路径或 named query 不对时先看这里。

变化关联
  位置：service/change
  问题：正式服务的变化查询或 [CHANGE] 摘要不对时看这里；可靠业务消息传输尚未实现。

HTTP 接口：api/http。人工工具：tools、review。图形显示：viewer。
API 返回正确但页面不对时才查 Viewer，不要反向修改 GraphDTO 或图数据。

人工先判断四件事：原始数据读对了吗；映射结果对了吗；Neo4j 图结果对了吗；API/页面能用吗。
Oracle 当前按“配置 → 单条 resync → review”核验，不要把单元测试当真实数据库连通测试。


离线接手审计 V1：缺口清单
========================

本轮从“没有聊天记录的第一次接手者”视角核对了 tools/*.cmd/*.sh、pom.xml、config、Viewer 和本手册。
共记录 20 项真实操作缺口：

部署阻塞（6 项，已修）
  1. service 以前每次先 Maven compile/exec，没有 Maven-free 正式运行入口。
  2. package 以前没有 target/lib 运行依赖布局，jar 不能单独离线启动。
  3. 没有集中 env 入口，四个 Neo4j 变量依赖人工在当前 CMD 逐个 set。
  4. 没有正式 runtime start/stop/status，也没有 PID/日志位置。
  5. Review CLI 和同步 CLI 以前只能走 Maven；现在有构建产物时优先直接 Java 启动。
  6. 没有 Kylin/Linux 对等 runtime.sh 和 env.sh.example。

非常容易人工踩坑（8 项，已修）
  1. JAVA_HOME/MAVEN_HOME 指向根目录还是 bin 目录容易混淆；脚本现在两种都接受。
  2. Windows env 只对当前 CMD 有效；脚本现在自动加载 tools\env.cmd（若存在）。
  3. Neo4j 启动脚本以前不会加载 env；现在会加载并明确提示缺项。
  4. 缺少 Java 产物、运行依赖、Viewer dist 或关键配置时以前只能等启动异常；check/runtime 会先提示。
  5. 18080 占用、旧 service 进程导致新 API 仍 404 的处理没有集中说明；已加入端口/PID/重启顺序。
  6. 没有简单的 service 日志和 PID 位置；正式 runtime 统一放在 runtime\logs、runtime\state。
  7. SLF4J/Log4j provider warning 容易被误认成启动失败；已明确以 health 和日志判断。
  8. 开发启动与正式离线启动入口混在一起；现在明确区分 service.cmd 和 runtime.cmd。

可以以后处理（6 项，明确延后）
  1. source-preview/source-mapping 等开发准备工具仍可依赖 Maven。
  2. 正式离线包的压缩、校验和发布清单。
  3. 密码 secret manager、Windows Service、systemd、Docker 正式部署和自动升级。
  4. Kylin 上的发行版级 Java/Neo4j 安装与权限自动化。
  5. preview 脚本参数中包含空格时的跨 shell 深度兼容。
  6. 远程运维、日志轮转和高可用。


任务 0：第一次在开发机启动
=========================

先区分两个入口：

  开发启动（允许 Maven）：tools\service.cmd
    用于改 Java、重新编译、开发调试；每次启动会 compile + exec。停止优先在该窗口按 Ctrl+C。

  正式离线运行（不依赖 Maven/npm）：tools\runtime.cmd start|stop|status
    使用 target\atm-knowledge-graph-1.0-SNAPSHOT.jar、target\lib 和已经构建好的 viewer\dist。
    首次交付前只需在有 Maven 的机器执行一次 `mvn.cmd -DskipTests package`。

1. 准备私有 JDK 17。pom.xml 的 maven.compiler.release 是 17；正式目标机不替换系统 Java 8。
   推荐复制模板并集中填写运行参数：

     copy tools\env.cmd.example tools\env.cmd
     notepad tools\env.cmd

   正式 runtime 要求 JAVA_HOME 指向 JDK 根目录或包含 java.exe 的 bin 目录；开发脚本也接受 PATH Java。
   检查：

     tools\check.cmd

     set "JAVA_HOME=C:\tools\jdk-17"
     set "PATH=%JAVA_HOME%\bin;%PATH%"
     java -version

2. 只有开发/构建时准备 Maven 3.9.x（3.9.11 已验证）。MAVEN_HOME 可填 Maven 根目录或 bin 目录：

     set "MAVEN_HOME=C:\tools\apache-maven-3.9.11"
     set "PATH=%MAVEN_HOME%\bin;%PATH%"
     mvn.cmd -version

3. env.cmd 中填写当前固定读取的四个 Neo4j 环境变量。密码只写在被 .gitignore 忽略的 env.cmd：

     set "ATMKG_NEO4J_URI=bolt://127.0.0.1:17687"
     set "ATMKG_NEO4J_DATABASE=neo4j"
     set "ATMKG_NEO4J_USERNAME=neo4j"
     set "ATMKG_NEO4J_PASSWORD=<开发实例密码>"

   这四个名字写死在 Neo4jConnectionSettings。固定项说明见
   docs\固定项与运行配置说明.md。

   正式 projectId 和 UID namespace 集中在
   src\main\java\org\atmkg\core\ProjectConstants.java；它们不是普通运行参数。IDENTITY_NAMESPACE 与
   本体 IRI 当前文本可能相同，但用途不同，不要用该常量拼 Class/Property IRI；本体 IRI 仍看唯一 TTL。

4. 使用 Docker Neo4j 5.26 开发实例：

     tools\neo4j-dev.cmd start
     tools\neo4j-dev.cmd status

   正常：看到 atmkg-neo4j-dev、Browser http://127.0.0.1:17474 和 Bolt 17687。
   失败：先查 Docker，再查四个环境变量。不要先改 Java。

   如果使用已有 Neo4j 安装而不是 Docker：

     set "ATMKG_NEO4J_HOME=<Neo4j安装目录>"
     tools\neo4j.cmd start

5. 开发启动：另开 CMD（脚本会自动加载 env.cmd），然后：

     tools\service.cmd

   正常：

     curl http://127.0.0.1:18080/api/v1/health

   浏览器：

     http://127.0.0.1:18080/viewer/

   config\sources.yaml 当前为 sources: [] 时，控制台应显示 Query/API-only。它仍要求 Neo4j，
   但不会加载正式 mapping 或启动 polling。

6. 正式离线启动/停止：

     tools\runtime.cmd start
     tools\runtime.cmd status
     tools\runtime.cmd stop

   日志在 runtime\logs\service.log 和 service-error.log。正式 runtime 不调用 Maven/npm。

7. 正常停止开发服务：在 service.cmd 窗口按 Ctrl+C，再执行：

     tools\neo4j-dev.cmd stop

   tools\neo4j-dev.cmd reset 会删除开发容器和数据卷，不是普通停止命令。

第一次接手的正式离线最短链：
  copy tools\env.cmd.example tools\env.cmd → 编辑 env.cmd → tools\check.cmd →
  tools\neo4j.cmd start/status（或连接已有 Neo4j）→ tools\runtime.cmd start/status →
  curl http://127.0.0.1:18080/api/v1/health → 打开 /viewer/ → tools\review.cmd →
  在 Viewer 输入 Review CLI 输出的 Browser-ready 只读 Cypher。
  停止顺序：tools\runtime.cmd stop → tools\neo4j.cmd stop；开发 service 则回原窗口 Ctrl+C。

Node/npm 只在改 viewer 或重建 viewer\dist 时需要：

  cd /d D:\Data\项目代码\atm-knowledge-graph-baseline\viewer
  npm ci
  npm test
  npm run build

正式 Viewer 只有 G6，不要重新加入 Sigma/Cytoscape/Graphology。


任务 0A：启动失败和旧进程排查
============================

Maven/JDK：
  `MAVEN_HOME` 应指向包含 `mvn.cmd` 的目录，或 Maven 根目录；不要把根目录误写成
  `...\bin` 后再让脚本重复拼接，也不要把 `JAVA_HOME` 写成 JRE。`tools\check.cmd` 会同时检查两种目录形态。
  env.cmd 由脚本加载，只作用于该脚本及其子进程；在一个 CMD 里 set，不会改变已经打开的另一个 CMD。

Neo4j 环境变量：
  缺 `ATMKG_NEO4J_URI`、`ATMKG_NEO4J_DATABASE`、`ATMKG_NEO4J_USERNAME` 或
  `ATMKG_NEO4J_PASSWORD` 时，先复制 env.cmd.example 并补齐；不要在每个 CMD 手工重复 set。

18080 被占用 / 新 API 仍返回 404：
  1. 优先回到原 service.cmd 窗口按 Ctrl+C，等待进程退出。
  2. 检查端口：

       netstat -ano | findstr :18080

  3. 记录末列 PID，再查进程：

       tasklist /FI "PID eq <PID>"

  4. 只有确认是本项目旧 service 且找不到原窗口时，才执行：

       taskkill /PID <PID> /T

     不要 `taskkill` 所有 `java.exe`，否则会误停 Neo4j、IDE 或其它项目。
  5. 修改代码或重新构建后，旧 service 不会热更新；必须停止旧进程，再重新启动 service.cmd 或 runtime.cmd。

SLF4J/Log4j provider warning：
  当前 warning 不是启动失败原因。先看 health、HTTP 端口和 runtime 日志；只有进程退出、health DOWN
  或出现后续异常时才按故障处理。

配置/资源缺失：
  `config/api.yaml`、`config/sources.yaml`、`mapping\字段映射.xlsx`、
  `ontology\atm_knowledge_graph.ttl` 或 `viewer\dist\index.html` 缺失时，先运行 `tools\check.cmd`。
  不要用 sources.local.yaml 替代正式 sources.yaml 启动正式 runtime；不要把缺文件误判为 Neo4j 故障。


任务 1：我要增加一个 Excel Sheet 或一组同结构 XLSX
====================================================

改 config\sources.yaml。当前 sources: []，接入第一个正式 Excel 源时，把它替换成下面结构；
已有 sources 时只在 sources 数组下追加一个 “- sourceId” 块，或在已有 source 的 objects 下追加
一个 objectName：

  sources:
    - sourceId: excel-main
      adapter: excel
      root: data/excel
      objects:
        route-node:
          files: "航路*.xlsx"
          sheet: 航路
          headerRow: 1
          keyFields: [航路代码, 序号]
          recordMode: row

逐项填写：

  sourceId      本物理源的稳定技术标识；mapping 工作簿必须写完全相同的值，例如 excel-main。
  adapter       固定写 excel。
  root          相对项目根目录的文件目录；不要把 XLSX 放项目根目录。
  route-node    sourceObject 名；mapping 三张正式 Sheet 的 sourceObject 列引用这个值。
  files         相对 root 的 glob。航路1.xlsx/航路2.xlsx 同结构时用 "航路*.xlsx"，不要拆两套配置。
  sheet         精确 Sheet 名，或从 1 开始的序号。
  headerRow     从 1 开始的表头行，默认 1。
  keyFields     Excel 表头中的稳定非空字段，按顺序拼成 SourceRecord.sourceKey。
  recordMode    row / group_first / adjacent_next。

三种 recordMode 的实际写法：

  # 每个有效行一条记录
  recordMode: row

  # 同一航路重复多行，只用“序号”排序后的第一行生成父记录
  recordMode: group_first
  groupBy: [航路代码]
  orderBy: 序号

  # 同一航路内“当前行 + 下一行”生成航段；末行不生成
  recordMode: adjacent_next
  groupBy: [航路代码]
  orderBy: 序号

files、sheet、headerRow、keyFields、groupBy、orderBy 都是物理读取规则，不是本体语义。
keyFields 只决定 SourceRecord.sourceKey；最终实体 UID 固定由实体 Class IRI 和字段映射.xlsx 的业务主键值决定。
不要用文件名、路径、Sheet 名或物理行号作为实体业务主键。

下一条命令必须显式指定正式配置，因为无参数 source-preview 会优先读取 sources.local.yaml：

  tools\source-preview.cmd config\sources.yaml excel-main route-node 5

正常：列出实际匹配文件、Sheet、总记录数，前 3～5 条 sourceKey 和字段与 Excel 一致。
失败：

  “未匹配 XLSX”       → 查 root/files。
  “Sheet 不存在”      → 查 sheet 名/序号。
  “sourceKey 字段为空”→ 查 keyFields 是否真是表头且每行有值。
  分组/顺序错误        → 查 groupBy/orderBy；不要改 ExcelSourceAdapter 加业务判断。

SourceRecord 正确后，再编辑 mapping\字段映射.xlsx；不要在 ExcelSourceAdapter 中写 Route/Airspace if。


任务 2：我要增加一个 Oracle/JDBC 表或 view
========================================

仍然只改 config\sources.yaml。在 sources 数组下复制下面的完整 source 块：

  - sourceId: jdbc-main
    adapter: jdbc
    driver: oracle.jdbc.OracleDriver
    url: jdbc:oracle:thin:@//DB_HOST:1521/SERVICE_NAME
    usernameEnv: ATMKG_JDBC_USERNAME
    passwordEnv: ATMKG_JDBC_PASSWORD
    fetchSize: 500
    objects:
      example-object:
        table: SCHEMA.TABLE_NAME
        keyFields: [ID]
        watermarkField: UPDATED_AT

DBA 必须提供并逐项确认：

  sourceId        稳定技术标识；这里仍写 jdbc-main，不写 oracle；mapping 必须逐字一致。
  adapter         固定写 jdbc；当前是通用 JDBC Adapter，不是 Oracle 专用 Adapter。
  driver          JDBC driver 类；当前 pom.xml 已带 ojdbc17 runtime Thin Driver。
  url             Oracle HOST、PORT、SERVICE_NAME；不要把账号或密码拼进 URL。
  usernameEnv     存放数据库用户名的环境变量名，例如 ATMKG_JDBC_USERNAME。
  passwordEnv     存放密码的环境变量名，例如 ATMKG_JDBC_PASSWORD。
  fetchSize       流式批读取提示，默认 500。
  example-object  sourceObject；mapping 用这个值，不是数据库表名。
  table / view    二选一。若读视图，删除 table 行并写 view: SCHEMA.VIEW_NAME。
  keyFields       与 ResultSet columnLabel 精确一致的稳定、非空且唯一业务键列；不会自动改大小写。
  watermarkField  可选时间列；只有配置它才能 scanChangedSince/polling。

启动前设置环境变量：

  set "ATMKG_JDBC_USERNAME=<数据库用户名>"
  set "ATMKG_JDBC_PASSWORD=<密码>"

ATMKG 当前 JDBC Adapter 只生成 SELECT，不会主动向 Oracle 业务源库执行
INSERT/UPDATE/DELETE/DDL。现场账号即使具有更高权限，本项目当前也不依赖这些写权限。
watermarkField 最好有数据库索引。当前 SQL 是 WHERE UPDATED_AT > ?，通过 setTimestamp 绑定，
ResultSet.getTimestamp 转 Instant；Oracle DATE/TIMESTAMP 列必须能稳定进行 JDBC Timestamp 比较。
NUMBER/VARCHAR2/DATE/TIMESTAMP 均通过 JDBC 通用 ResultSet 读取，不进入 Core 类型体系。

配置和环境变量就绪后，先在写图前查看 JDBC SourceRecord：

  tools\source-preview.cmd config\sources.yaml jdbc-main example-object 5

正常：只读取并显示前 5 条，包含 sourceKey、字段名和字段值；同时显示 table/view、keyFields 和可选
watermarkField，不显示密码。填写或检查 Mapping 后，再在写图前查看 MappingResult：

  tools\source-mapping-preview.cmd config\sources.yaml mapping\字段映射.xlsx jdbc-main example-object 5

然后执行 tools\sync.cmd，先选“重新同步一条记录”，输入 source-preview 显示的 sourceKey，最后用
tools\review.cmd 检查图。开发/排障可以使用 Preview；正式同步仍由 tools\sync.cmd 执行。

连接失败先查 driver/url/环境变量/SELECT 权限；缺列查 table/view 实际结果。新增表不要改
JdbcSourceAdapter 或 SourceAdapterFactory；只有通用 JDBC 标识符、游标、PreparedStatement 读取机制变化
才进 JdbcSourceAdapter。只有正式增加第三种 SourceAdapter 类型时才改 SourceAdapterFactory。
以后更换其他 JDBC 数据库时，原则上只替换 runtime driver、URL 和源对象配置，不修改 Core。


任务 3：我要把源里的一个字段写入现有实体
=========================================

例：把源字段 route_name 映射到现有 Route 的
urn:atm-knowledge-graph:routeName。

1. 先在 ontology\atm_knowledge_graph.ttl 搜索 routeName。已存在就不要新增 TTL 定义。
2. 打开 mapping\字段映射.xlsx 的“属性映射”Sheet，复制同一个实体类的相邻行，填写：

     sourceId      与 config/sources.yaml 完全一致，例如 excel-main
     sourceObject  objects 下的键，例如 route-parent
     实体类        urn:atm-knowledge-graph:Route
     源字段/路径   SourceRecord 中的字段，例如 route_name；相邻模式可写 current.字段 或 next.字段
     本体属性      urn:atm-knowledge-graph:routeName
     转换          留空，或仅使用 trim/upper/lower/integer/long/decimal/boolean
     必填          是或否

3. 先明确指定一个 sourceObject 查看 mapping 结果，Excel/JDBC 命令相同：

     tools\source-mapping-preview.cmd config\sources.yaml mapping\字段映射.xlsx <sourceId> <sourceObject> 5

   工具复用正式 SourceAdapter，只消费前 5 条 SourceRecord，不写 Neo4j。旧的三参数 Excel 开发用法仍可用；
   正式配置包含 JDBC 时必须使用上面的五参数形式，避免默认遍历全部表或视图。

4. 再只重同步一条：

     tools\sync.cmd

   选“重新同步一条记录”，选择 sourceObject，输入 source-preview 显示的 sourceKey。

正常：mapping preview 的 Route 属性出现 routeName；review 查询该实体时属性存在。
失败：SourceRecord 没字段回任务 1/2；有字段但 MappingResult 没属性，核对 sourceId、源对象、
源字段/路径和是否必填。不要修改 DefaultMappingEngine、Neo4jGraphStore 或 QueryService。

JDBC 连接失败时核对 config\sources.yaml 的 driver/url/table-or-view/keyFields、usernameEnv/passwordEnv
对应环境变量和 SELECT 权限；Preview 失败不会写入 Neo4j。


任务 4：我要新增一种实体
========================

例：新增一个当前 TTL 尚不存在的 NavPoint（只示范操作顺序，不表示已批准该业务类）。

1. 先确认 ontology\atm_knowledge_graph.ttl 中确实没有同义 Class；如果已有 NavigationAid、
   ReportingPoint 或 RouteNode 能表达需求，不要重复建类。
2. 在唯一正式 TTL 中增加 Class，并根据已确认语义选择父类。不要创建第二份运行时 TTL。
3. 打开 mapping\字段映射.xlsx 的“实体映射”Sheet，新增一行：

     sourceId      config/sources.yaml 中的 sourceId
     sourceObject  objects 下的键，不是 files/table/sheet 的值
     实体类        新 Class 的完整 IRI
     业务主键      SourceRecord 中稳定字段路径

4. 在“属性映射”Sheet 至少映射业务键和需要的显示属性。
5. Excel/JDBC 都先明确指定目标入口预览：

     tools\source-preview.cmd config\sources.yaml <sourceId> <sourceObject> 5
     tools\source-mapping-preview.cmd config\sources.yaml mapping\字段映射.xlsx <sourceId> <sourceObject> 5

   核对结果后执行 tools\sync.cmd → 3. 重新同步一条记录，再执行 tools\review.cmd。

6. 两种来源都执行 mvn.cmd test；确认单条 resync 正确后，再按需要 fullSync 一个入口。

正常：MappingResult 中 class IRI 正确，同一业务键重复运行得到同一 UID。
失败：“未知实体类”查 TTL IRI；“业务主键缺失”查 SourceRecord 字段路径；UID 改变查业务键。
不要改 DeterministicIdentityResolver 来迎合文件名、表名或 Sheet 名，否则已有身份会失配。


任务 5：我要新增一种图关系
==========================

例：Route --hasSegment--> RouteSegment 已是当前真实关系，可照它的结构检查新关系。

1. 在 ontology\atm_knowledge_graph.ttl 中先定义 object property、domain、range。当前示例：

     atmkg:hasSegment a owl:ObjectProperty ;
       rdfs:domain atmkg:RouteSequence ;
       rdfs:range atmkg:RouteSegment .

2. 打开 mapping\字段映射.xlsx 的“关系映射”Sheet，新增一行：

     sourceId        产生这条关系的 SourceRecord.sourceId
     sourceObject    产生这条关系的 SourceRecord.objectName
     关系类型        object property 完整 IRI
     起点类          domain 对应 Class IRI
     起点引用字段    当前关系事实 SourceRecord 中存放起点业务键值的路径
     终点类          range 对应 Class IRI
     终点引用字段    当前关系事实 SourceRecord 中存放终点业务键值的路径
     说明            人工解释来源和方向

3. 实体、属性和关系映射都按 sourceId + sourceObject 选择。关系来源不需要同时配置起点/终点实体
   mapping；端点 canonical UID 固定由关系行中的端点 Class IRI + 当前记录引用值生成。引用字段可来自
   current.x / next.x，但它们不是跨表 join 定义。端点实体仍必须通过其各自权威来源先写入图，GraphStore
   会检查端点存在性和 TTL domain/range。
4. 执行：

     mvn.cmd test
     tools\sync.cmd
     tools\review.cmd

   先 resync 一条；ReviewTool 选“完整一跳”或“按关系类型”检查实际方向和端点。

关系端点缺失时先查两端实体 mapping 和 locator，不要让 QueryService 临时制造关系。
RouteSegment ↔ Airspace 空间拓扑当前没有计算实现，不能通过 query template 猜坐标生成。

左侧必须填 GraphNodeDTO.kind。它来自 canonical KGEntity 的 class short name，在 API 返回 GraphDTO

假设 API/Viewer 实际看到 kind=NavPoint，且 query-templates.yaml 已存在
navpoint-neighbors、navpoint-routes，写法是：

    NavPoint:
      - navpoint-neighbors

  RouteSegment:

执行：

  mvn.cmd -Dtest=ChangeQueryRuleRegistryTest,GraphChangeAssociationProjectorTest,KgServiceMainTest test

正式 KgServiceMain 会严格加载 change-query-rules.yaml。UPSERT 写图成功后会依次执行 Neighborhood

任务 8：我要开启 JDBC polling
=============================

1. 先在 config\sources.yaml 对目标 JDBC object 配置 watermarkField，例如 updated_at。
2. 确认数据库列有索引、类型可被 JDBC Timestamp 读取，并且现场数据库账号能执行 SELECT。
3. 改 config\sync.yaml：

     sync:
       initialFullImport: true
       incremental: true
       compensation: true
       manualResync: true
       eventCarriesAuthoritativeData: false
       polling:
         enabled: true
         intervalSeconds: 30
         lookbackSeconds: 5
         scopes:
           - sourceId: jdbc-main
             sourceObject: route-row
             initialWatermark: "2026-08-24T00:00:00Z"

   sourceId 必须等于 sources.yaml 的 sourceId；sourceObject 必须等于该 source 的 objects 键。
   initialWatermark 只在该 scope 尚无 checkpoint 的首次启动使用，必须是人工确认的
   ISO-8601 UTC 起点，不能用“当前时间”猜。已有 checkpoint 时，重启优先从 checkpoint 继续。
   lookbackSeconds 会从 checkpoint 向前回看，降低相同时间戳晚到记录被漏掉的风险。
   eventCarriesAuthoritativeData 必须保持 false；polling 只发现身份，SyncService 会 readByKey 回读。

4. 执行：

     mvn.cmd -Dtest=SyncRuntimeConfigTest,SyncRuntimeAssemblerTest,JdbcPollingTriggerAdapterTest test
     tools\service.cmd

正常：控制台显示 sync runtime configured; polling=true；成功处理后生成
runtime\state\polling-checkpoints.json。下一轮从 checkpoint 减去 lookback 后扫描，因此可能重复读取；
这是预期的 at-least-once 行为，stable sourceKey/UID 和 replaceProjection 会吸收重复处理。

失败：

  scope 不存在             → 对照 sources.yaml 的 sourceId/objects 键。
  未配置 watermarkField    → 在目标 JDBC object 增加该列名。
  initialWatermark 格式错  → 使用带 Z 的 Instant，例如 2026-08-24T00:00:00Z。
  checkpoint无法读取       → 停止 service，先备份损坏文件，再删除后重新启动。

checkpoint 只在整轮 ChangeEvent 被 SyncService 成功处理后推进，值取成功源记录中的最大
sourceTimestamp；空扫描、读取/Mapping/GraphStore/consumer/checkpoint写入失败都不推进。
文件使用临时文件写完后再替换，实际 JSON 已由 .gitignore 排除，不提交源码仓。

需要人工重扫时：先停止 service，备份后删除整个
runtime\state\polling-checkpoints.json。下次启动时所有 scope 都回到各自 initialWatermark；
这会产生重复扫描，但不会自动清图。不要在 service 运行时手改 JSON。

当前 JdbcSourceAdapter 仍严格执行 WHERE watermark > ?；回看通过传入更早的 effectiveSince 实现，
没有 Oracle 专用 SQL。有限 lookback 不能保证接住窗口以外的极晚记录，timestamp polling 也不发现
hard DELETE。本实现是 at-least-once，不是 exactly-once。
initialFullImport=true 不会在服务启动时自动 fullRebuild。

任务 10：我要同步整个入口，还是重建全部图
==========================================

tools\sync.cmd 菜单：

  “2. 同步一个数据源入口” = fullSync
    只选一个 sourceObject，读两遍当前记录：先建实体端点，再 replaceProjection。
    不 clearProject。用于新接入一个入口或批量刷新当前仍存在的记录。
    它不知道哪些旧 key 已在源库 hard DELETE。

  “1. 全量重建当前正式数据源” = fullRebuild
    先 clearProject，再同步 config/sources.yaml 中列出的全部 sourceObject。
    只有首次完整装载、图严重失配、或 TTL/mapping 变化明确要求全图重建时使用。
    操作前确认 sources.yaml 范围完整；漏配会在清图后造成缺失。
    必须输入“确认重建”。

  “4. 补偿扫描” = compensateSince
    手工输入 ISO-8601 起始时间。JDBC 必须有 watermarkField；不解决 hard DELETE。

  “5. 查看当前同步配置”
    显示 sourceId/sourceObject/adapter/watermark、polling interval/lookback，以及每个 polling scope
    当前 checkpoint；尚未生成时显示 initialWatermark。不显示密码、JDBC URL 或业务数据。

任务 13：本体或 Mapping 改了以后怎么处理
==========================================

唯一正式本体是 ontology\atm_knowledge_graph.ttl，人工 Mapping 入口是 mapping\字段映射.xlsx。
历史版本只由 Git 保存。改文件不等于 Neo4j 已变化：正式运行链必须重启 service 重新加载，再执行
resync、fullSync 或经确认后的 fullRebuild。

A. 新增普通 datatype property

  1. 修改唯一 TTL；
  2. 关闭 Excel，执行 --refresh：

       mvn.cmd -q -DskipTests compile org.codehaus.mojo:exec-maven-plugin:3.5.0:java "-Dexec.mainClass=org.atmkg.tools.Phase1CheckMain" "-Dexec.args=--refresh"

  3. 在字段映射.xlsx 的“本体参考”确认新增术语，再向“属性映射”新增一条实际 Mapping；
  4. 运行 Phase1CheckMain（不带 --refresh），确认正式 Mapping 校验通过：

       mvn.cmd -q -DskipTests compile org.codehaus.mojo:exec-maven-plugin:3.5.0:java "-Dexec.mainClass=org.atmkg.tools.Phase1CheckMain"

     再运行 mvn.cmd test；
  5. 重启 service，使 TTL/Mapping 重新加载；
  6. 对受影响 sourceObject 执行 resync 或 fullSync；
  7. 用 tools\review.cmd 检查结果。

  refresh 只重建“本体参考”，不会向三张正式 Mapping Sheet 追加行，也不会覆盖人工已填内容。
  普通属性新增不需要修改 DefaultMappingEngine、Neo4jGraphStore 或 QueryService。

B. 新增普通实体或关系

  基本步骤与 A 相同。新增实体还要人工确认业务主键和 sourceId/sourceObject；新增关系还要人工确认
  关系事实来源 sourceId/sourceObject、起点类、终点类、引用字段以及 TTL 中的 domain/range。不要自动猜。

C. 删除或改名 Class / Property

  refresh 不会自动删除旧 Mapping，也不会自动改名。旧完整 IRI 失效后应由 Mapping 校验明确报错，
  人工确认后再修改或删除对应行。然后重启服务并重新同步受影响数据；变化范围很大、删除大量 Mapping
  或无法可靠判断范围时，确认 sources.yaml 完整后再使用 fullRebuild。

  Mapping 删除某属性或关系后，需要重新同步对应源记录，replaceProjection 才会清掉该 SourceRef
  不再生成的旧属性或旧关系。

D. 身份相关变化

  Class IRI、实体业务主键、UID namespace 的变化可能改变实体 kg_uid，并影响关系端点和外部引用。
  这不是普通修改：必须先人工评估，通常按全图重建或专门的身份迁移处理，不能用普通 --refresh。
  ObjectProperty IRI 变化也会改变关系 UID。

E. 删除 sourceObject / 数据源

  从 sources.yaml 删除 object 或 source，不会自动让 Neo4j 删除旧投影。先人工清理对应投影，或者确认
  正式数据源范围后执行 fullRebuild。当前没有自动 source retirement。


任务 14：两个 sourceObject 要补充同一个实体
===========================================

例：airport-base 提供 ZBAA 名称，airport-position 提供 ZBAA 经纬度。

在 mapping\字段映射.xlsx 的“实体映射”中为两个 sourceObject 各写一行 Airport：

  - sourceId 可以相同；
  - sourceObject 分别写 airport-base、airport-position；
  - 业务主键字段名可以不同，但值必须都表达同一个稳定机场代码 ZBAA。

同步后 Neo4jGraphStore 为 (entityUid, SourceRef) 保存 KGEntityContribution，并合成一个 KGEntity。
相同属性相同值允许；同一属性不同值会显式报冲突并回滚，不会“后写覆盖前写”。
删除 position contribution 后，base 仍存在则 canonical Airport 保留。

KGEntityContribution 是内部技术节点，不能出现在 QueryService/GraphDTO/Viewer/业务节点统计中。
多来源关系 contribution 当前未实现；同一关系事实仍只配置一个权威来源。


任务 15：我该运行哪个工具
==========================

  tools\neo4j-dev.cmd
    Docker 开发 Neo4j start/stop/status/reset；reset 删除开发卷。不读 sources.yaml。

  tools\neo4j.cmd
    转发到 ATMKG_NEO4J_HOME\bin\neo4j.bat，控制已有安装。

  tools\service.cmd
    开发启动 KgServiceMain、Query API 和 G6 Viewer；每次先 Maven compile，sources 非空时装配同步，polling 启用时写图。

  tools\runtime.cmd
    正式离线 start/stop/status；只使用已构建 target jar/target/lib 和 viewer\dist，不调用 Maven/npm。

  tools\check.cmd
    接手前检查私有 JDK、可选 Maven、四个 Neo4j 变量、关键配置/产物和 18080 端口；不自动修复。

  tools\env.cmd.example
    Windows 集中环境模板；复制为被忽略的 tools\env.cmd 后由各脚本自动加载。

  tools\env.sh.example / tools\runtime.sh
    Kylin/Linux 对应环境模板和正式离线 runtime 入口。

  tools\source-preview.cmd
    检查 Excel/JDBC → SourceRecord，不写 Neo4j；无参数优先 sources.local.yaml。

  tools\source-mapping-preview.cmd
    检查 Excel/JDBC SourceRecord → MappingResult；无参数使用 fixture mapping，不写 Neo4j。
    正式 JDBC 使用 sources + mapping + sourceId + sourceObject + limit 五参数形式。

  tools\sync.cmd
    读取正式 sources/sync/TTL/mapping，调用正式 SyncService，会写 Neo4j，不改源数据。

  tools\review.cmd
    只读 Neo4j，显示图/数据结果和 Browser-ready Cypher；不依赖 sources.yaml。

  只读 Cypher 后端
    POST /api/v1/graph/cypher 返回 CypherResultDTO：
    有序 columns、JSON-safe rows、GraphDTO graph 和 meta；标量/表格查询的 graph 可以为空。
    服务端先用 Neo4j EXPLAIN + QueryType.READ_ONLY 判定，再以 AccessMode.READ 执行；
    不接受 EXPLAIN/PROFILE、params 或写查询。表格固定最多 1000 行；节点/关系规模由 Cypher
    的 LIMIT 与 config/api.yaml 服务端硬上限共同控制，超限均显式失败。
    本轮未修改 Viewer；Table/Raw/Graph 的前端适配后续单独开发。
