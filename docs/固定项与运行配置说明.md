# 固定项与运行配置说明

## config 中哪些 YAML 会影响运行

`config/` 中当前正式运行时直接读取的 YAML 只有三份：

- `sources.yaml`：Excel/JDBC 数据源、源对象和物理读取规则，由 `SyncRuntimeAssembler` 读取；
- `sync.yaml`：同步能力和 JDBC polling 配置，由 `SyncRuntimeAssembler` 读取；
- `api.yaml`：HTTP 地址、路径、查询深度和结果规模上限，由 `KgServiceMain` 读取。

项目内还有其他用途明确的 YAML：`queries/query-templates.yaml` 由正式查询服务读取；
`queries/change-query-rules.yaml` 由正式 `KgServiceMain` 读取，用于 UPSERT GraphChange 的 Association 查询；
`review/queries.yaml` 只供人工 Review 工具读取。它们不属于 `config/` 运行配置。

`change-query-rules.yaml` 缺失或格式非法会使正式服务启动失败。当前 GraphChange 结果只输出控制台摘要，
没有 durable sink；DELETE Projector 仍跳过，`tools/sync.cmd` 也不走 GraphChange 输出链。

## Neo4j 地址和账号从哪里设置

Neo4j 连接通过启动进程中的四个环境变量设置：

- `ATMKG_NEO4J_URI`
- `ATMKG_NEO4J_DATABASE`
- `ATMKG_NEO4J_USERNAME`
- `ATMKG_NEO4J_PASSWORD`

这些名称固定在 `Neo4jConnectionSettings` 中。仓库不保存真实地址、用户名或密码。

## 当前唯一 TTL 在哪里

当前唯一正式本体是 `ontology/atm_knowledge_graph.ttl`，服务和同步工具直接读取这个路径。
历史版本由 Git 保存，不提供 YAML 开关切换多份本体。新增本体术语后，仍需人工维护
`mapping/字段映射.xlsx`；`[待映射]` 只表示待填写，不表示映射已经生效。

## projectId 当前是什么性质

当前正式 `projectId` 是 `atm-knowledge-graph`，用于隔离 Neo4j 中本项目的节点、关系和维护操作。
它集中定义在 `src/main/java/org/atmkg/core/ProjectConstants.java` 的 `PROJECT_ID`，由正式服务、
同步工具、Review 工具和 Neo4j 验收入口使用，不是运行时可随意切换的配置项。
修改它会让已有图数据与新写入数据落入不同项目范围，必须先设计数据迁移和核验方案。

## UID namespace 为什么不能随便改

当前 UID namespace 是 `urn:atm-knowledge-graph:`。稳定 UID 由类语义、稳定业务键和该 namespace
共同形成。只改 namespace 会让同一业务对象生成新的 UID，并使已有关系端点和外部引用失配；
它集中定义在 `ProjectConstants.IDENTITY_NAMESPACE`，属于需要全图迁移的固定项，不是普通运行开关。

`IDENTITY_NAMESPACE` 与本体 IRI 当前文本可能相同，但用途不同，不应把本体 Class、Property 或关系 IRI
从该常量生成。确认本体 IRI 时仍以唯一正式 TTL 为准。

## 查询完整性原则

- 一跳查询返回完整一跳关系，不做随机抽样或 top-N；
- K-hop 返回约束深度内到达的节点，以及这些节点之间原图已有的完整关系；
- 不使用静默 `LIMIT` 截断结果；超过 `config/api.yaml` 的节点或关系上限时显式失败；
- QueryService 只读取图中已有事实，不临时计算空间关系或制造业务关系；
- named query 只使用 `queries/query-templates.yaml` 中受控的 QuerySpec 模板，不接受 raw Cypher。

以上内容是项目固定规则，不是可以用 true/false 临时关闭的运行选项。
