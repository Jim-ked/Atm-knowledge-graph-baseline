# 依赖策略

源码、开发资源和部署产物分离。候选第三方资源放在外部开发资源库，不进入本源码仓。

对效果敏感且可替换的叶子依赖采用“主选 + 备选资源”方式准备；正式代码在同一接口边界上只接当前主选，实际效果不佳时再替换，不预先维护两套业务实现。

当前可准备的候选方向包括：
- 本体解析：Apache Jena / Eclipse RDF4J；
- 映射工作簿：Apache POI / 可替换 XLSX 读取库；
- Viewer：G6 / Cytoscape.js / Sigma.js + Graphology，并为各候选准备其实际需要的最小布局/交互依赖；
- REST 外壳：在 API 实现阶段选择成熟实现，调用端不依赖具体框架。

Neo4j 是当前明确图数据库，不为“备份”同时开发另一套图数据库实现。APOC、GDS、n10s 等不得成为基础构图和查询闭环的硬依赖。

未被选入当前实现的候选资源不要求逐项做工程级烟测；选用后直接使用本项目测试数据验证，效果不佳即可替换。
